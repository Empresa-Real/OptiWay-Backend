## 1. Rendimiento y Base de Datos (Severidad Alta)

### ⚠️ Problema N+1 extremo en memoria en [InventarioService.java](./src/main/java/com/example/optiway/application/service/InventarioService.java#L65-L114)
En la consulta de inventario:
```java
List<Inventario> inventarios = inventarioRepositoryPort.findByTiendaId(tiendaId);

return inventarios.stream()
    .filter(inventario -> {
        // Query 1 a la base de datos POR CADA REGISTRO
        Producto producto = productoRepositoryPort.findById(inventario.getProductoId()).orElse(null);
        ...
    })
    .map(inventario -> {
        // Query 2 A LA BASE DE DATOS DEL MISMO PRODUCTO POR CADA REGISTRO
        Producto producto = productoRepositoryPort.findById(inventario.getProductoId()).orElse(null);
        ...
    })
```
* **Impacto**: Si una tienda tiene 200 productos, este endpoint ejecuta **401 consultas SQL individuales** a PostgreSQL.
* Además, el filtrado por nombre y categoría se está haciendo en la memoria de la JVM mediante Streams en vez de delegarlo al motor de base de datos con un `JOIN` y cláusulas `WHERE`.
* **Solución**: Crear un método de consulta en repositorio con JPQL o Proyección/DTO (`JOIN ProductoJpaEntity`) para traer inventario + producto en **1 sola query**, aplicando los filtros y paginación en la BD.

### ⚠️ Condición de Carrera (*Race Condition*) en [IngresoMercanciaService.java](./src/main/java/com/example/optiway/application/service/IngresoMercanciaService.java#L85-L115)
* Al recibir mercancía, se hace lectura en memoria `inventario.getCantidadActual() + cantidad` y luego `guardar()`.
* Si ocurren dos ingresos casi simultáneos del mismo producto al mismo CD, ocurrirá un *lost update* o violación de concurrencia.
* Se recomienda usar un update atómico en base de datos (`UPDATE inventario_cd SET cantidad = cantidad + :ingreso WHERE ...`) o bloqueo pesimista/optimista (`@Version`).

## 2. Seguridad y Control de Acceso (Severidad Alta / Media)

### ⚠️ Falta validación de roles en [IngresoMercanciaService.java](./src/main/java/com/example/optiway/application/service/IngresoMercanciaService.java)
* En `consultarInventario` (HU-12) sí se valida que el usuario sea el encargado de la tienda:
  ```java
  if (!usuario.getId().equals(tienda.getEncargadoId())) {
      throw new AccesoDenegadoException("No tiene permisos para consultar esta tienda");
  }
  ```
* Pero en `registrarIngreso` (HU-18), **no se valida ningún rol**. Cualquier usuario autenticado (un cliente, un cajero o un encargado de tienda) puede registrar ingresos en cualquier Centro de Distribución. Debería verificarse que tenga rol `ADMINISTRADOR` o `ENCARGADO_CD`.

### ⚠️ Semántica HTTP incorrecta en excepciones
* En [InventarioService.java](./src/main/java/com/example/optiway/application/service/InventarioService.java#L53): Si la tienda no existe, lanza `AccesoDenegadoException("La tienda no existe")`. En [ApiExceptionHandler.java](./src/main/java/com/example/optiway/infrastructure/adapter/in/rest/ApiExceptionHandler.java#L24) esto responde un **`HTTP 403 FORBIDDEN`** en lugar de un **`HTTP 404 NOT FOUND`**.
* En [IngresoMercanciaService.java](./src/main/java/com/example/optiway/application/service/IngresoMercanciaService.java#L67-L83): Si el usuario, centro de distribución o producto no existen, lanza `IllegalArgumentException` devolviendo **`HTTP 400 BAD REQUEST`** en vez de **`HTTP 404 NOT FOUND`**.

## 3. Arquitectura y Buenas Prácticas REST (Severidad Media)

1. **Fuga del Modelo de Dominio**:
   * En [Inventario.java](./src/main/java/com/example/optiway/domain/model/Inventario.java), se añadieron campos planos de presentación (`nombreProducto`, `categoriaProducto`, `stockBajo`) para resolver la vista.
   * [InventarioController.java](./src/main/java/com/example/optiway/infrastructure/adapter/in/rest/InventarioController.java#L28) expone directamente el modelo de dominio `List<Inventario>`. En arquitectura hexagonal se recomienda retornar un DTO (`InventarioResponse`) desde el controlador.
2. **Convenciones REST**:
   * [IngresoMercanciaController.java](./src/main/java/com/example/optiway/infrastructure/adapter/in/rest/IngresoMercanciaController.java#L28) retorna `void` (HTTP 200). Para un `POST` de creación, debe responder `@ResponseStatus(HttpStatus.CREATED)` (HTTP 201) y preferiblemente devolver el identificador o resumen del registro creado.
3. **Bean Validation**:
   * [RegistrarIngresoMercanciaRequest.java](./src/main/java/com/example/optiway/infrastructure/adapter/in/rest/RegistrarIngresoMercanciaRequest.java) no utiliza anotaciones como `@NotNull`, `@Positive`, `@NotBlank` ni `@Valid` en el `@RequestBody` del controlador, delegando toda la validación a `if`s imperativos dentro del caso de uso.
4. **Ubicación de DTOs**:
   * `RegistrarIngresoMercanciaRequest` se ubicó en la raíz de `adapter.in.rest` en lugar del paquete `adapter.in.rest.dto` que sigue el resto del backend.

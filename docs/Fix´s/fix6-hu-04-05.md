# Informe de Correcciones y Refactorización: HU-04 y HU-05 — Gestión de Productos (Fix 6)

Este documento detalla las soluciones técnicas, adaptaciones en la arquitectura hexagonal del backend y refactorizaciones de robustez aplicadas tras el merge de las ramas **HU-04 (Crear Producto)** y **HU-05 (Editar Producto)** en el repositorio `OptiWay-Backend`.

---

## 1. Resumen Ejecutivo y Alcance

* **HU-04 (Crear Producto):** Permite a los usuarios con rol `ADMINISTRADOR` dar de alta productos en el catálogo maestro, asegurando identificador único en mayúsculas, nombre, categoría, precio no negativo, unidad de medida opcional y estado inicial `activo`.
* **HU-05 (Editar Producto):** Permite a los usuarios con rol `ADMINISTRADOR` actualizar parcialmente datos de productos existentes (nombre, categoría, precio mayor a cero y unidad de medida), protegiendo campos inmutables como el `id`, el `identificador` y el `estado`, y registrando una auditoría en la tabla de ediciones de producto.

---

## 2. Brechas y Errores Detectados Previos al Fix

| Componente | Brecha Identificada | Impacto |
| :--- | :--- | :--- |
| **Ramas Git (HU-04)** | Archivos comiteados sin extensión `.java` (`CrearProductoUseCase`, `ObtenerProductosUseCase`, `ProductoService`, `ProductoController`). | El compilador `javac`/Maven los ignoraba; los servicios y endpoints no compilaban ni se registraban. *(Nota: Corregido al hacer merge de HU-05, que los renombró adecuadamente).* |
| **Capa REST (Controller)** | `POST /api/productos` recibía directamente el modelo de dominio `@RequestBody Producto producto` en lugar de un DTO específico. | Exposición del modelo interno; riesgo de inyección o sobreescritura de campos no deseados (`id`, `estado`); inconsistencia con `HU-05` (que sí usaba DTO). |
| **Arquitectura Hexagonal** | `ProductoService` importaba y capturaba `org.springframework.dao.DataIntegrityViolationException`. | Ruptura de la separación de capas: la capa de aplicación/dominio quedó acoplada a excepciones de persistencia de Spring Data. |
| **Seguridad / Manejo JWT** | Se invocaba `UUID.fromString(jwt.getSubject())` directamente sin validar nulidad de `jwt` ni formato UUID. | Si una petición no traía token o el subject era inválido, arrojaba `NullPointerException` (error 500) en lugar de un rechazo limpio por seguridad (401/403). |
| **Endpoint Catálogo (`GET`)** | `GET /api/productos` no tenía verificación explícita en el método. | Se requería verificar que estuviese resguardado por `SecurityConfig` para evitar consultas no autenticadas anónimas. |

## 3. Remediaciones y Mejoras Implementadas

### A. Creación del DTO `CrearProductoRequest`
Se creó la clase [CrearProductoRequest.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/infrastructure/adapter/in/rest/dto/CrearProductoRequest.java) en la capa de adaptadores REST:
* Contiene únicamente los campos editables al momento de crear: `identificador`, `nombre`, `categoria`, `precio` y `unidadMedida`.
* Evita que el cliente pueda inyectar `id` autogenerado o alterar el `estado`.

### B. Desacoplamiento y Robustez en `ProductoController`
En [ProductoController.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/infrastructure/adapter/in/rest/ProductoController.java):
1. **Uso del DTO:** El método `crearProducto` recibe `@RequestBody CrearProductoRequest request` y mapea los datos limpios al modelo `Producto`.
2. **Extracción Segura de Identidad (`extraerAuthUserId`):**
   ```java
   private UUID extraerAuthUserId(Jwt jwt) {
       if (jwt == null || jwt.getSubject() == null) {
           return null;
       }
       try {
           return UUID.fromString(jwt.getSubject());
       } catch (IllegalArgumentException e) {
           return null;
       }
   }
   ```
   Si el token no está presente o el subject no es un UUID válido, retorna `null`. El servicio [ProductoService.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/application/service/ProductoService.java) intercepta el `authUserId == null` y arroja `AccesoDenegadoException`, respondiendo un `403 Forbidden` limpio vía `ApiExceptionHandler`.

### C. Restauración de la Arquitectura Hexagonal
1. **Adaptador de Persistencia ([ProductoRepositoryAdapter.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/infrastructure/adapter/out/persistence/ProductoRepositoryAdapter.java)):**
   Se encapsuló la llamada a `productoJpaRepository.save(entity)` dentro de un bloque `try-catch` que captura `DataIntegrityViolationException` (infraestructura) y la traduce a `ProductoDuplicadoException` (dominio/aplicación).
2. **Servicio de Aplicación ([ProductoService.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/application/service/ProductoService.java)):**
   Se eliminó por completo la dependencia con `org.springframework.dao.DataIntegrityViolationException`. La capa de aplicación delega la persistencia al puerto `ProductoRepositoryPort` sin conocer detalles de base de datos.

### D. Verificación del Endpoint de Consulta (`GET /api/productos`)
Se verificó en [SecurityConfig.java](file:///c:/Users/Fixer/Desktop/Git%20Kraken/OptiWay-Backend/src/main/java/com/example/optiway/infrastructure/config/SecurityConfig.java) que la regla global `.anyRequest().authenticated()` exige un JWT válido para cualquier endpoint no explícitamente público. De esta forma:
* Usuarios anónimos reciben `401 Unauthorized`.
* Usuarios autenticados (cualquier rol: administrador, encargado, planificador) pueden consultar el catálogo de productos para operaciones de inventario y ventas.

## 4. Matriz Comparativa

| Aspecto | Antes del Fix | Después del Fix |
| :--- | :--- | :--- |
| **Payload `POST /api/productos`** | Modelo de dominio crudo `Producto` | DTO tipado `CrearProductoRequest` |
| **Manejo de concurrencia / duplicados** | `try-catch (DataIntegrityViolationException)` en `ProductoService` | Captura y traducción en `ProductoRepositoryAdapter` |
| **Parsing del Subject JWT** | `UUID.fromString(jwt.getSubject())` (vulnerable a NPE) | Helper `extraerAuthUserId(jwt)` con fallback a `403` |
| **Acoplamiento Spring Data en Aplicación** | Sí (`DataIntegrityViolationException`) | No (100% agnóstico y hexagonal) |
